# Maintainers

## Current maintainers

This is a single-maintainer open-source project. The maintainer's role is to:

- Review pull requests on a best-effort basis (no SLA).
- Cut releases when there is meaningful change.
- Respond to security advisories per `SECURITY.md`.
- Decide on architectural changes via Issue discussion before code lands.

The maintainer does NOT promise:

- Time-bound response to issues.
- Custom feature development.
- Migrations between major versions on a fixed schedule.
- Support for self-hosted runner deployment on specific platforms.

If you depend on this project commercially or on a deadline, fork it. Apache 2.0 explicitly allows this.

## Contact

For security reports: `multiagent-protocol-security@<see-github-profile>`. Replace `<see-github-profile>` with the actual address listed on the maintainer's GitHub profile when you read this — we do not hardcode an email in this file to keep it spam-resistant.

For everything else: open an Issue on GitHub.

## Becoming a maintainer

If you have landed five or more non-trivial PRs and want to take on triage / review responsibilities, open an Issue tagged `maintainer-request`. The existing maintainer(s) will discuss in the issue. There is no formal vote; this is a small project, not a foundation.

## Stepping down

A maintainer may step down at any time by opening an Issue tagged `maintainer-stepdown`. If no maintainer remains active for 90 days, the project is considered unmaintained and the README should be amended to say so. Any contributor may open a PR adding the "unmaintained" banner after the 90-day window.
